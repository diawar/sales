# Проверка письма и собственная статистика конкретной рассылки

Подэтап от 12.11.2026. Реальная отправка отключена. После реализации — остановка для проверки заказчиком.

## Интерфейс

В разделе **Рассылки** у каждого сохранённого черновика появились действия:

- **Проверить письмо** — открывает отдельный экран этой рассылки.
- **Статистика** — открывает собственные события этой рассылки.
- **Демо-статистика** — прежние синтетические события; они не объединяются с собственными событиями.

В проверке показываются название и версия рассылки, имя/версия сохранённого шаблона, тема, сохранённый отправитель и адрес для ответов.

Для персонализации можно выбрать контакт среди получателей рассылки или задать проверочные значения вручную. Поиск — по названию клиента или email, первые 20 подходящих контактов. У физических лиц поле «Компания» остаётся пустым. При отсутствии email подставляется `preview@example.invalid`; его можно заменить. Выбранные поля можно редактировать только в проверке, карточка клиента не меняется. Подстановка имени/города использует текущие поля клиента, не исторический снимок его профиля.

Кнопка **Проверить подстановку и ссылки** не создаёт писем, токенов или подписок. Она проверяет значения без запасного текста, сохранённый HTML, тему после подстановки, URL, отправителя, настройку origin и наличие переменной отписки. Показывает недостающие переменные и замечания шаблона. Доступность внешних сайтов, DNS и SMTP не проверяется. Для публичной доступности ссылок остаётся отдельный неподтверждённый пункт.

**Подготовить проверочное письмо** создаёт только тестовое письмо, собственные ссылки и тестовую ссылку центра подписок. HTML-предпросмотр не загружает внешние ресурсы, не переходит по ссылкам и сам не создаёт открытия. Есть отдельные кнопки проверки пикселя/переходов, ссылка отписки и действие **Статистика этого письма**. Непосредственное открытие страницы отписки безопасно; применяется только POST с CSRF.

В статистике доступны проверочные/рабочие письма отдельно, конкретное письмо, email, вид события, период (включительно, Asia/Qyzylorda), сортировка по времени и страницы по 25 строк. Карточки учитывают все типы событий в выбранном режиме/письме/email/периоде; вид события фильтрует только журнал. Число подготовленных писем и список писем не ограничиваются периодом событий. Первые 50 писем доступны в селекторе; email помогает сузить выборку. В журнале видна версия рассылки при подготовке письма.

## Сохранённые данные и изоляция

- Источник письма — `EmailCampaign.template_snapshot` и `sender_snapshot`. Если очередь уже существует, используются её `snapshot.template` и `snapshot.sender`.
- Изменение живого шаблона или живого отправителя не подменяет проверяемую копию. Для изменения будущего письма нужно обновить черновик, пока он не зафиксирован очередью.
- Проверка передаёт версию кампании и идентификатор/версию очереди. Если после открытия экрана черновик изменился либо появилась очередь, сервер возвращает 409 и требует обновления; токены не создаются.
- При наличии очереди список клиентов дополнительно ограничивается адресами её зафиксированного состава. Связь контакта с аудиторией берётся из текущей БД; прошлое состояние карточки клиента не восстанавливается.
- `TrackedMessage.campaign` устанавливается сервером из URL. Подстановка чужого клиента отклоняется. События другой рассылки, общие письма из настроек без привязки, `CampaignTestEvent` и рабочие события не смешиваются с тестовыми событиями выбранной рассылки.
- Миграция `0033` добавляет `TrackedMessage.preparation_snapshot`: версия/источник копии, ID контакта (если выбран), реквизиты отправителя и метаданные версии шаблона. Исходные bearer-токены и подготовленный HTML в это поле не записываются.
- Само письмо, ссылки и события остаются тестовыми даже при подстановке данных реального клиента. Нет изменения `Address`, рабочих согласий, исключений, активности или очереди.
- В этой проверке формируются `From` и `Reply-To` из сохранённого отправителя; передача SMTP отсутствует. Владение доменом не подтверждается форматом реквизитов.
- Повторы одного пикселя/ссылки не увеличивают счётчики первого наблюдения. Открытия/переходы не доказывают прочтение или действие человека и не создают статус доставки.

## API

- `GET /api/campaigns/<id>/mail-check?query=...` — источник, версия, реквизиты, контакты.
- `POST /api/campaigns/<id>/mail-check` — `action=diagnose` или `prepare`, версия из GET, проверочный email, `values` (`name`, `company`, `city`), необязательный `contact_id`. Принимается только `is_test=true`, `send=false`.
- `GET /api/mail-tracking?campaign_id=<id>&mode=test|real` — собственная статистика. Дополнительные параметры: `message_id`, `query`, `kind`, `from`, `to`, `direction`, `page`. Неверная/несуществующая рассылка не превращается в общую выборку.

После перезагрузки восстанавливаются рассылка и вкладка. События и метаданные хранятся в БД. Введённые проверочные поля, фильтры, подготовленный HTML и исходные ссылки после перезагрузки не восстанавливаются; новую подготовку нужно выполнить заново. Подготовка не сбрасывает уже отозванную тестовую подписку: при повторной проверке отписки с таким email страница покажет, что подписка уже отозвана. Для нового полного сценария можно выбрать другой проверочный адрес `@example.invalid`.

## Приёмка

1. Открыть «Рассылки», сохранить черновик с аудиторией, шаблоном и отправителем.
2. Нажать **Проверить письмо**. Убедиться, что показаны сохранённые данные.
3. Выбрать клиента или заполнить значения. Проверить диагностику, включая недостающие поля переменных, если они есть в шаблоне.
4. Подготовить письмо без отправки. В собственной статистике должны оставаться нули до нажатия проверочных кнопок.
5. Проверить открытие, переход и отписку. Открыть **Статистика этого письма**: события должны относиться к текущей рассылке и её версии.
6. Переключить источник на рабочие письма: проверочные события пропадают. Проверить период, поиск, тип и сортировку.
7. Перезагрузить страницу: рассылка/вкладка и события сохраняются.

В локальной БД оставлен проверочный черновик **«Проверка — письмо и собственная статистика»**, проверочный отправитель `preview@example.invalid`, одно письмо на `campaign-preview@example.invalid` и три события (открытие, переход, отписка). Реальная отправка и очередь не запускались. Для подстановки выбран существующий контакт без email; поля контакта не менялись.

Проверки: **136 тестов**, в том числе 13 новых для связи с рассылкой; проверки Django, миграций и синтаксиса JavaScript; ручной сценарий в браузере, включая восстановление после перезагрузки и отделение рабочих событий. Первичная мобильная эмуляция в этом подэтапе не была подтверждена. Последующая мобильная проверка и исправления от 12.11.2026 выполнены отдельно: [STAGE_CAMPAIGN_MAIL_MOBILE.md](STAGE_CAMPAIGN_MAIL_MOBILE.md).
