# Автоматические аудитории по активности — тестовый подэтап

Открытие: «Аудитории» → «Открыть тестовый расчёт». Дополнительный вход — «Аналитика» → «Аудитории по активности (тест)» для текущего набора/рассылки.

Все группы виртуальные и вычисляются по тестовым событиям при каждом GET. Они не создают Audience/SavedSegment и не меняют Client/Contact/Address, согласия, исключения, очереди и реальные метрики. В мастере отправки эти группы не появляются. Реального транспорта нет, can_send=false. Никакого сопоставления синтетического email с реальным клиентом для изменения его активности не выполняется.

Правила по умолчанию:
- активный: хотя бы один переход за последние 90 дней;
- пассивный: переходов нет, минимум 3 разных доставленных письма за 90 дней и последнее доставлено не менее 7 дней назад;
- мало данных: не хватает писем либо не завершилось ожидание после доставки;
- исключён: тестовая отписка или окончательная ошибка, с приоритетом над переходами. Эти тестовые признаки не меняют реальные запреты.

Открытия показываются отдельно, не заменяют переходы и не доказывают прочтение. Временная ошибка не исключает получателя. Отписка/окончательная ошибка из доступной истории не исчезают при смене окна активности. В этом тестовом потоке нет события повторного согласия, поэтому их снятие по новому клику не моделируется.

Границы периода и ожидания включаются. События позже даты расчёта игнорируются. Доставки дедуплицируются по идентификатору письма на получателя; повторные уведомления не делают одну доставку несколькими и не обновляют её исходную дату. Для тестовой статистики одна рассылка — одно письмо на получателя, для отдельной демонстрации используется message_key. Дата исходной доставки — самая ранняя запись для этого письма.

Источники:
1. ActivityTestEvent — отдельный тестовый набор. Демонстрация содержит 28 событий и 11 получателей: 1 активный, 4 пассивных, 4 с недостаточными данными, 2 исключённых. Повторное заполнение не дублирует события.
2. CampaignTestEvent — уже существующая тестовая статистика, в режиме только чтения, с выбором набора/рассылки. Отдельная демонстрация активности не изменяет статистику (демонстрационный набор статистики сохранил 330 событий).

Интерфейс: изменяемые тестовые правила (окно 1–730 дней, писем 1–20, ожидание 0–180 дней), дата расчёта для моделирования старения, карточки, причины классификации, фильтр группы/email, сортировка, страницы по 25 записей, ручное тестовое событие. Правила сохраняются только в sessionStorage этой вкладки. Автопересчёт каждые 15 секунд при открытом экране и отсутствии редактирования правил; фоновой записи членства в реальную БД нет. Скрытый экран не опрашивается.

API:
- GET /api/activity-audiences: source=activity_demo|statistics, campaign_id=demo|all|id, lookback_days, min_delivered, quiet_days, as_of, state, query, sort, direction, page.
- POST /api/activity-audiences/demo: идемпотентное заполнение только ActivityTestEvent.
- POST /api/activity-audiences/test-events: event_id UUID, recipient, kind, message_key для delivered, error_type для error, occurred_at необязательно. Только тестовый поток, source=real/test_only=false отклоняются. Повтор ID не дублирует данные; другой payload с тем же ID отклоняется.
