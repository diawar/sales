# Статистика рассылок — тестовые события, подэтап для приёмки

В меню «Аналитика» добавлен раздел «Статистика рассылок». Из списка рассылок можно открыть статистику конкретной кампании кнопкой «Статистика».

Данные этого подэтапа хранятся только в CampaignTestEvent. Это отдельный журнал синтетических событий. Реальной отправки, пикселей, редиректов, публичной отписки, приёма вебхуков провайдера и обновления активности клиентов нет. Тестовые отписки/ошибки не меняют Address, реальные подписки, запреты и состояние очереди. Событие очереди «Имитировано» автоматически не превращается в событие доставки.

Функции:
- карточки передачи на отправку, доставки, открытий, переходов, отписок и ошибок;
- уникальные получатели и общее количество событий, отдельно;
- доли доставки и ошибок среди переданных на отправку, открытия/переходы/отписки среди доставленных;
- динамика по дням, до 90 последних дней с событиями;
- до 20 ссылок по числу переходов, все/уникальные клики;
- временные и окончательные ошибки;
- журнал с фильтром типа события, поиском email, сортировкой времени и страницами по 25 строк;
- выбор рассылки и периода, восстановление раздела/фильтров после обновления;
- ручное добавление тестового события и идемпотентное заполнение демонстрацией.

Повторные открытия/клики с разными ID увеличивают общее число событий, но не уникальных получателей. Повтор запроса с одним UUID не увеличивает даже число событий; другой payload с уже занятым UUID отклоняется. Email нормализуется casefold. Доли используют пересечение получателей с обоими видами событий в выбранном периоде: отсутствующие события не домысливаются. При нулевой базе выводится «—». Временная ошибка и последующая доставка могут относиться к одному получателю, поэтому категории не взаимоисключающие. Открытие — загрузка пикселя, не подтверждение прочтения; в этом подэтапе даже пиксель не загружается, всё создаётся синтетически.

Период и суточная группировка: часовой пояс settings.TIME_ZONE (Asia/Qyzylorda), обе границы даты включаются. Фильтры журнала не изменяют верхние показатели. Уникальные получатели за день могут повторяться между днями; сумма дневных значений не обязана совпадать с общим числом уникальных.

Демонстрационный набор не связан с реальной рассылкой (campaign=NULL) и не входит в «Все рассылки». В нём 100 адресов example.invalid, 330 событий за 7 дней: 100 переданных, 80 доставок, 70 открытий от 50 получателей, 40 кликов от 30, 20 отписок и 20 ошибок. Заполнение повторно не создаёт дублей. Набор оставлен в локальной БД для проверки. Одиночная тестовая отписка ui-statistics-check@example.invalid, созданная при UI-проверке формы, удалена; клиенты, шаблоны и очереди не менялись.

API:
- GET /api/campaign-stats?campaign_id=demo|all|<id>&from=YYYY-MM-DD&to=YYYY-MM-DD&kind=...&query=...&direction=asc|desc&page=1
- POST /api/campaign-stats/test-events — campaign_id (либо demo), event_id UUID, recipient, kind; опциональные occurred_at, detail, link (обязательно для click), error_type temporary/permanent (для error). Только source=test.
- POST /api/campaign-stats/demo — campaign_id (либо demo), синтетический набор.

Реальные события позже потребуется хранить отдельно или явно отделять источником; эти API не являются интеграцией с провайдером.

Проверено: 78 тестов статистики, очереди, мастера, исключений/DNS, шаблонов, тестовой отправки, сегментов и таблицы контактов. Для статистики проверены идемпотентность, уникальность, показатели демонстрации, изоляция, часовые границы, страницы, фильтры, отсутствие подмены доставки открытием, запрет реального source и отсутствие mail/SMTP/network вызовов даже при включённом SMTP. UI: заполнение/повтор, счётчики, фильтр открытий, вторая страница, ручное событие и восстановление после обновления.
