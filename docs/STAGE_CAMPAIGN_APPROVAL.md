# Согласование рассылок — 12.11.2026

В разделе «Рассылки» у каждого черновика появилась кнопка «Согласование».
Менеджер и администратор передают сохранённую версию на проверку; одобрить или
вернуть её может администратор. Для возврата обязателен комментарий до 2000 символов.
Редактор и наблюдатель могут просматривать состояние и версию на проверке.
Администратор может проверять собственные черновики: разделение автора и проверяющего
между двумя разными сотрудниками в этом подэтапе не требуется.

Статусы: не согласована, на проверке, одобрена, возвращена, нужно повторное согласование.
Для решения используются версия черновика и отдельная версия согласования;
устаревшие решения из второго окна отклоняются с HTTP 409.

На проверку сохраняются письмо, отправитель, аудитории, расписание и количество
получателей после исключений. Состав допустимых адресов сравнивается по SHA-256;
адреса получателей не копируются в журнал согласования. HTML хранится в снимке
согласования, а журнал содержит только действие, версии, статус, автора и комментарий.
Предпросмотр изолирован, внешние изображения и переходы отключены.

Сохранение изменений рассылки или её шаблона снимает согласование и создаёт запись
в журнале. Дополнительно сравниваются актуальные настройки шаблона и отправителя,
а перед решением и начальным запуском — состав получателей. При изменении состава
окно согласования показывает необходимость повторной проверки, запуск блокируется.
GET не меняет состояние базы. Персональные комментарии следует писать без паролей и ключей.

Новая очередь, сценарий и репетиция требуют одобрения актуальной версии всех
используемых рассылок. Версия одобрения фиксируется в снимке запуска. При её снятии
или замене обработка останавливается на ближайшем шаге; продолжение старой версии
запрещено. Пауза и отмена доступны и без одобрения. Для уже зафиксированной очереди
действует прежнее правило: изменение письма и состава требует новой рассылки/очереди.
Уменьшение состава после подготовки очереди из-за новых исключений по-прежнему
обрабатывается её проверками допуска; новые контакты в готовую очередь не добавляются.

Одобрение разрешает только имитацию и не заменяет проверку готовности. Допускается
передать и просмотреть черновик с нулём получателей; подготовка его очереди останется
заблокированной. SMTP и реальная отправка запрещены всем ролям.

Ранее созданные рассылки не одобряются автоматически. Миграция 0042 добавляет отдельную
таблицу согласования, клиентские данные не изменяет. Перед миграцией сохранена
локальная резервная копия SQLite. В браузере проверен существующий тестовый черновик
№6 без получателей: передан, одобрен, повторно передан и возвращён с комментарием.
Все четыре действия подписаны учётной записью admin; итог — «Возвращена», очередей нет.

Дополнительно по запросу пользователя уменьшена плотность настольного интерфейса:
меню 12 px, иконки 16 px, пункты 34 px, шапка 52 px, боковая панель 200 px.
При viewport 1920×900 меню целиком помещается без внутренней прокрутки. На мобильном
сохранены прежние размеры элементов для нажатия. Окно согласования проверено на
390 px: горизонтального переполнения нет.

Проверки: 427 тестов успешно, включая 9 тестов согласования — права, возврат,
устаревшие решения, снятие одобрения, изменение состава, остановка очереди,
запрет обхода через сценарии/репетиции, CSRF и отсутствие сетевой отправки.
Также пройдены Django check, проверка отсутствия новых миграций, JavaScript syntax
check и git diff --check. Legacy-тесты отдельных механизмов явно отключают вход;
новые тесты согласования выполняются с включённой авторизацией и правами.

После этого подэтапа остановиться для проверки пользователя. Публикация и Git push
не выполнялись.
