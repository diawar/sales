# Общая приёмка локальной копии — 13.11.2026

Проверялась локальная копия на Windows, `http://127.0.0.1:8173/`.
SMTP и реальная отправка выключены. Коммит, публикация, изменение DNS и проверка
боевого сервера в этот проход не выполнялись.

Полная приёмка запуска после перезагрузки ОС остаётся открытым пунктом. Windows
не перезагружалась: на машине пользователя открыты рабочие приложения. Чтение
конфигурации планировщика и инвентаризация процессов через Windows Management
Infrastructure в текущей среде вернули «Отказано в доступе». Это не подтверждает
наличие или отсутствие настроенного автозапуска. Новую задачу планировщика и
службу Windows не создавали.

## Исправления

1. Отключённый пользователь теперь сохраняет назначенную роль в списке и форме.
   Ранее эффективная роль становилась пустой, а select мог визуально выбирать
   первый вариант «Администратор». Назначенная роль отделена от действующих прав:
   у отключённой учётной записи прав нет, после включения возвращается прежняя роль.
2. При ограничении попыток изменения собственного пароля страница администратора
   больше не теряет список пользователей, роли и административные элементы.
   Ответ 429 содержит `Retry-After: 900`.
3. Открытое мобильное меню блокирует фоновые страницы и элементы шапки через inert,
   удерживает Tab/Shift+Tab внутри меню, закрывается по Escape и возвращает фокус
   на гамбургер. Добавляемые во время загрузки фоновые страницы также блокируются.

Добавлен `scripts/start_local.ps1`: запуск локального сервера из любого рабочего
каталога, проверка конфигурации и применённых миграций, явное отключение SMTP,
только адрес `127.0.0.1`. Скрипт проверен запуском из `C:\Windows\System32`.
Он не устанавливает автозапуск, не запускает сборщики и не является production-службой.

- Фактические ширины viewport: 320, 390, 768 и 1440 px. Соответствующие ширины
  страницы: 305, 375, 753 и 1425 px (разница обусловлена вертикальным scrollbar).
- На 320/390 px проверены главная, список рассылок, библиотека и открытие сохранённого
  шаблона, карточка клиента, подсказки импорта, готовность, статистика и согласование.
- Ширина открытой карточки клиента и импорта на 320 px — 273 px, согласования —
  296 px; горизонтального переполнения диалогов нет.
- Проверено открытие и закрытие меню, выбор раздела, Shift+Tab с гамбургера к
  последнему пункту и Escape с возвратом фокуса. Фоновые main получают inert.
- Страница учётных записей проверена на 320 px. Рабочих пользователей и паролей
  для проверки ролей не создавали и не изменяли; сценарии изменений — в тестовой БД.

## Данные и запуск

Снимки `outputs/acceptance-before-2026-11-13.json`,
`outputs/acceptance-after-restart-2026-11-13.json` и
`outputs/acceptance-final-2026-11-13.json` содержат только количества и SHA-256,
без содержимого клиентских записей и секретов. Проверены 19 таблиц/связей:
клиенты, аудитории, контакты, телефоны, история источников, данные Over-shop,
подписки и исключения, письма, отправители, рассылки, согласования, роли,
пользователи и индивидуальные отметки чтения.

Изменённых таблиц между начальным и итоговым снимком: **0**. Технические поля
фоновой DNS-проверки адресов исключены из контрольной суммы, бизнес-поля адреса
включены. Аудит входа и рабочие сессии также не сравниваются как неизменяемые данные.
Инструмент — `scripts/acceptance_snapshot.py`.

В базе: 24 621 контакт, 3 рассылки, очередей отправки — 0. Согласование тестовой
рассылки №6 осталось на проверке (версия 5). Проверка SQLite `PRAGMA quick_check`
вернула `ok`; файл БД после запуска из системного каталога остался прежним в `data/`.
Сервер оставлен работающим, вход admin сохранился после повторных запусков.

В начале прохода вчерашняя сессия была просрочена согласно 8-часовой настройке.
Пользователь самостоятельно вошёл; пароль агенту не передавался. В рамках
неистёкшей сессии остановка/запуск сервера повторного входа не потребовали.

**442 теста пройдены**. Добавлены проверки сохранения роли отключённого пользователя,
полного набора читаемых API для всех ролей, отсутствия повышения прав через

и блокировки реальной отправки также прошли.

Пройдены Django check, makemigrations --check --dry-run, синтаксис JavaScript и
git diff --check. Для изменений пользователей и данных Django создавал отдельную
тестовую БД; рабочие клиенты при приёмке не импортировались и не редактировались.
