# Проверка готовности рассылки — подэтап для приёмки

В списке «Рассылки» у сохранённого черновика появилась кнопка «Проверка готовности». GET /api/campaigns/<id>/readiness формирует новый отчёт без сохранения состояния, одобрения запуска и отправки. Кнопка «Обновить проверку» заново рассчитывает данные и время проверки.

Отчёт показывает четыре состояния проверок: готово, внимание, исправить, ожидание подключения/подтверждения. Итог needs_changes означает наличие локальных препятствий; waiting_integration — отсутствие локальных ошибок при оставшихся внешних подтверждениях. can_send всегда false независимо от SMTP-настроек. Это не разрешение на отправку.

Проверяются:
- актуальный технический допуск email: архив, запреты, результат ранее выполненной DNS-проверки и совпадение регистра адреса;
- количество уникальных email, ожидающие/терминальные записи очереди и технически допущенные адреса;
- для черновика — текущие аудитории и все подкатегории; для существующей очереди — её зафиксированный список, оставшиеся pending/retry и сохранённые копии шаблона/отправителя;
- наличие темы, текста, ссылки {{unsubscribe_url}}, неподдерживаемого HTML, обработчиков событий, неизвестных переменных и заготовочного текста;
- синтаксис ссылок и изображений, HTTP(S), mailto, tel, демонстрационные адреса; URL не посещаются, доступность не проверяется;
- данные персонализации по фактическим клиентам: отсутствие значения/запасного текста, неоднозначные клиенты с одним email, тема после подстановки (переносы/длина), небезопасные или некорректные URL после подстановки. До 10 примеров проблем. company не выдумывается для физических лиц;
- формат имени, email и reply-to отправителя;
- актуальность запланированной даты, часовой пояс;
- сведения о согласии: подтверждено источником, неизвестно, отозвано, отдельно для всего состава и технически допущенных.

Подтверждение источника признаётся только при активной подтверждённой OverShopSubscription с рубриками, датой, source_hash и без review_reason. Это подтверждение импортированной подписки, а не юридическая проверка её объёма. Соответствие рубрик теме конкретной акции остаётся отдельной неподтверждённой проверкой. Регистрация, заказ и публичная публикация email не считаются согласием. Неактивная подписка сама по себе не считается отзывом. Действующий запрет «Отписка» имеет приоритет над положительной подпиской; при отсутствии достаточного подтверждения состояние неизвестно. Этот подэтап не создаёт новые согласия и не снимает запреты.

Отдельно показываются ещё не подключённые рабочая отписка, подтверждение домена/SPF/DKIM/DMARC, соответствие политике провайдера и реальный транспорт. Параметры SMTP/пароли не возвращаются. Отчёт не вызывает DNS, не проверяет сайты через HTTP и не отправляет почту. Значения DNS берутся из базы; отсутствие даты или возраст более 30 дней помечаются предупреждением.

Отчёт — актуальный расчёт, а не блокировка базы на будущее. Перед реальным запуском потребуется новая проверка. Он не меняет адреса/подписки, список исключений, кампанию, очередь, тестовые события и метрики клиентов. Реальный шлюз запуска в этот подэтап не входит.

Валидация: 92 теста готовности, статистики, очереди, мастера, email-исключений/DNS, шаблонов, тестовой отправки, сегментов и таблицы контактов. В тестах проверены доказательства подписки, неизвестное/отозванное согласие, приоритет запретов, повторный расчёт, отсутствие персональных данных/запасного текста, неоднозначность, HTML/URL/заголовочные ошибки, неизменность сохранённой копии очереди, терминальные записи, пустая аудитория, расписание, отправитель, отсутствие утечек секретов и network/mail/SMTP/DNS-вызовов. POST к отчёту запрещён.

UI-проверка проведена на временном черновике с существующей аудиторией «Бизнес»: 11 798 уникальных email, отчёт строился около 4 секунд. Проверены кнопка, причины препятствий, разбиение по разделам и повторный расчёт. Созданные агентом временные черновик и отправитель readiness-ui-check@example.invalid удалены после проверки; пользовательские клиенты/шаблоны/согласия не менялись. Новых моделей или миграций нет.

Для приёмки: сохранить/открыть свою рассылку → вернуться к списку → «Проверка готовности» → просмотреть причины → «Обновить проверку». После этого подэтапа остановиться для проверки пользователя.
