# Автоматический сбор Kaspi, 11.11.2026

Локально подключён и включён HTTP-сборщик публичных продавцов компьютеров и комплектующих. Ни серверная версия, ни GitHub этим этапом не обновлялись.

## Охват и источники

Первый город каталога — Алматы, код 750000000. Обходятся процессоры, системные блоки, видеокарты, оперативная память, материнские платы, накопители, блоки питания, охлаждение, корпуса и другие комплектующие. Это не утверждение о полном охвате Казахстана. Контактный город магазина извлекается из его опубликованного адреса, а не из выбранного города покупателя.

Из публичного кода витрины подтверждены запросы `/yml/product-view/pl/results`, `/yml/offer-view/offers/<productID>`, `/yml/merchant-info/p/<merchantID>/details` и `/support?c=<city>`. Используется корректный Referer страницы товара/каталога/магазина; без него API отвечал 403. Cookies, авторизация магазина, ключи, подмена браузерной сессии, прокси и обход капчи не используются. Это внутренние публичные запросы витрины, а не договорный API с гарантией совместимости. Неизвестный формат требует проверки оператора.

Сохраняются ID/имя магазина, телефон с типом, адрес, город адреса, категории и ссылки на товары, где найден продавец. Цены, заказы, рейтинги и метрики качества из ответов не сохраняются. В этом адаптере контактов читается телефон; email не придумывается. Рекламные согласия не добавляются.

## Очередь и управление

Миграция 0020 создаёт KaspiCollection, KaspiTask и KaspiMerchant; существующий пилот подхватывается без новых клиентов. Этапы очереди: страница категории → страницы предложений товара → адрес магазина → телефон магазина. Ключ задачи уникален в цикле; один магазин читается один раз в цикле, при повторном обнаружении дополняются категории и источники. Клиент сохраняется по `kaspi:merchant:<ID>`; общие телефоны/названия не объединяют магазины.

Один HTTP-запрос за шаг, не чаще раза в 10 секунд. Очередь и ошибки находятся в БД; перезапуск и пауза не сбрасывают страницы. После завершения доступной очереди следующий цикл через 24 часа. Первые страницы категорий идут первыми, затем приоритетно сохраняются контакты найденных магазинов. Пустая страница каталога завершает его ветку. Предложения обходятся по total/страницам. Повторяющаяся или неполная страница не считается успешным завершением.

401/403 и неизвестный формат останавливают сбор с сохранением проблемной задачи. 429 учитывает Retry-After в секундах или HTTP-дату; временные ошибки повторяются с задержкой, максимум три попытки, затем задача остаётся на проверке. Ошибки не превращаются в пустой список продавцов. В интерфейсе есть «Включить сбор», «Пауза», «Повторить отложенные», heartbeat процесса, счётчики очереди/проверки, фильтры и страницы магазинов. Повтор отложенных не включает остановленный сбор сам по себе.

## Запуск

```text
python manage.py migrate
python manage.py collect_kaspi
```

Однократный шаг: `collect_kaspi --once`, также соблюдает паузу/задержку. Команда не включает сбор сама: это отдельное действие оператора в интерфейсе. После перезагрузки компьютера команду нужно запустить снова; на сервере отдельная управляемая служба. Не запускать одновременно несколько установок с независимыми БД для одного обхода. Lease защищает от одновременных запросов двух процессов к одной БД.

## Проверка

На живом источнике обработаны первые страницы всех 10 категорий, появились новые предложения и магазины; сохранено не менее 12 магазинов с телефонами против 10 в исходном пилоте. Проверены пауза/продолжение в UI и перезапуск процесса с сохранением очереди. Сбор оставлен включённым. Полный обход на момент приёмки ещё не завершён; счётчики будут увеличиваться.

Тестами проверяются формы публичных запросов, отсутствие cookies, разделение города адреса, неверный ID/URL/категория, ответы 403/429/500, Retry-After, продолжение страниц, повторные страницы, ограничение частоты, lease и пауза во время запроса. Перед миграцией создана SQLite backup с проверкой целостности. Скриншот текущей проверки — docs/screenshots/kaspi-automatic.png, только локально.
