Проверено 6267 аккаунтов: 5750 загружены, 16 администраторов исключены, 38 возможных служебных записей и 463 записи с признаками организаций оставлены на проверку. Из 5750 аккаунтов 8 существовали после пилота, 5742 созданы сейчас. Для 11 аккаунтов сохранены замечания; некорректный email не создаётся как адрес отправки, отсутствующее имя заменено подписью с ID источника.

Перенесены все 79 подписок классического модуля Битрикс. Все активны на сайте, 78 подтверждены и одна ожидает подтверждения. Текущий статус в приложении: 74 подтверждены без найденных исключений, одна ожидает подтверждения, четыре на проверке из-за связи с исключённым аккаунтом/email. Исходные флаги подтверждения не изменялись. 16 подписчиков, отсутствовавших среди загруженных клиентов, сохранены отдельными контактами с идентичностью подписки. Даты создания/подтверждения и рубрика 1 перенесены без преобразования исходного времени; выгрузки Битрикс не содержат отдельного часового пояса.

## Правила

- Аккаунт идентифицируется только по `overshop:user:<ID>`. Одинаковые имя/email разных ID не объединяют клиентов.
- Подписка имеет собственный ID в OverShopSubscription, адрес, необязательную связь с клиентом, исходный USER_ID, флаги активности/подтверждения, рубрики, даты, контрольную сумму и время импорта.
- Анонимная подписка — свидетельство для адреса, не доказательство владения аккаунтом. При совпадении адреса с уже загруженным клиентом новый клиент не создаётся, связь владения не придумывается. Иначе создаётся `overshop:subscriber:<ID>`.
- Подписки исключённых аккаунтов сохраняются для проверки, не включаются в аудиторию подтверждённых получателей.
- Архив и локальные запреты адреса имеют приоритет; импорт не снимает их. Подтверждение в модуле сайта не является самостоятельным юридическим заключением о согласии.
- Ручные данные, история контактов и источники сохраняются. Партия записывается атомарно, повтор тех же файлов не создаёт дублей. Исчезновение строки из новой выгрузки не трактуется как явная отписка.
- Это перенос снимка, не постоянная синхронизация с Битрикс. Отправка сообщений не подключалась.

## Повтор на другой установке

Создать защищённую резервную копию серверной БД. Обновить код и применить миграцию `0019_overshopsubscription`. Два **приватных** CSV передать отдельно от GitHub:

```text
python manage.py migrate
python manage.py import_overshop --customers /private/customers.csv --subscribers /private/subscribers.csv
python manage.py import_overshop --customers /private/customers.csv --subscribers /private/subscribers.csv --commit
```

Без `--commit` команда только проверяет входные файлы. Для SQLite перед записью автоматически создаётся согласованная резервная копия в data/backups с проверкой целостности. Для PostgreSQL резервную копию обеспечивает оператор до запуска. Выгрузки, резервные копии и результаты лежат вне Git; не помещать их в публичную папку сайта.

CSV клиентов — авторизованный SELECT из Битрикс с колонками CUSTOMER_ID,FIRST_NAME,LAST_NAME,EMAIL,PHONE,MOBILE,CITY,COMPANY,REGISTERED_AT,ORDERS_TOTAL,ORDERS_PAID,ORDERS_CANCELLED,COMPANY_ORDERS,GROUP_NAMES. ORDERS_PAID считает только оплаченные неотменённые заказы. CSV подписок: SUBSCRIBER_ID,CUSTOMER_ID,EMAIL,ACTIVE,CONFIRMED,DATE_INSERT,DATE_UPDATE,DATE_CONFIRM,RUBRIC_IDS. Флаги Y/N, рубрики разделены `|`, анонимный CUSTOMER_ID пустой. Связь рубрик проверена: b_subscription_rubric.SUBSCRIPTION_ID / LIST_RUBRIC_ID. Пароли, токены и суммы заказов не выгружались.
