# Серверный автозапуск — подготовка и отмена Windows

Статус: подготовлено локально, остановлено для проверки. На сервер не устанавливалось.

Локальная задача `OVER-Sales-Local-8173` удалена со всеми триггерами и управляемым
процессом. Удалены четыре скрипта её установки/запуска/управления/проверки. Ручной
`scripts/start_local.ps1` сохранён. Приватная квитанция удаления —
`data/private/autostart/removal-status.json`; БД и журналы сохранены.

Подготовлены:

- `deploy/systemd/over-sales.service`: автозапуск Linux/systemd, ограниченный
  пользователь, проверки перед стартом, восстановление после сбоя, внешний data-dir.
- `deploy/gunicorn.conf.py`, `requirements-server.txt`, `mailer/wsgi.py`:
  WSGI за существующим HTTPS proxy, loopback-порт, без публичного runserver.
- `mailer/production.py`: обязательные секрет/домен/каталог данных, защищённые
  cookie, HTTPS, принудительное отключение SMTP и dummy email backend.
- `deploy/sales.env.example`, `deploy/nginx-sales-location.conf` и
  [инструкция агенту](SERVER_AUTOSTART.md): обследование сервера, сохранение текущей
  службы и БД, установка, проверка настоящего reboot и откат.
- Over-shop использует DATA_DIR для импортов и отчётов; локальный путь по умолчанию
  сохранён. Тесты предпросмотра используют изолированный временный DATA_DIR.

Проверки 13.11.2026:

- 446 тестов Django прошли, включая 4 проверки серверного профиля.
- На отдельной временной SQLite: `check --deploy --fail-level ERROR`, `migrate`,
  `migrate --check`, загрузка WSGI — успешно. Даже с SALES_SMTP_ENABLED=1 и
  прежним DJANGO_SETTINGS_MODULE=mailer.settings точка WSGI использует production:
  can_send=false, анонимный закрытый API=401, HTTP перенаправляется на HTTPS.
- Единственное deploy-предупреждение W004: HSTS оставлен до проверки настоящего TLS.
- Python-конфиги синтаксически корректны, `git diff --check` прошёл.
- Контроль 19 таблиц/связей относительно снимка перед отменой автозапуска:
  изменённых таблиц нет (`outputs/server-autostart-data-2026-11-13.json`).
