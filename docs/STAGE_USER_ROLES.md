# Роли и права пользователей — 12.11.2026

Роли назначает администратор в `/accounts/`. Новый обычный пользователь и прежняя
учётная запись без назначения получают минимальную роль «Наблюдатель».

| Возможность | Администратор | Менеджер | Редактор шаблонов | Наблюдатель |
|---|---|---|---|---|
| Просмотр клиентов, шаблонов, рассылок и статистики | Да | Да | Да | Да |
| Изменение клиентов, импорт, экспорт, аудитории, подписки | Да | Да | Нет | Нет |
| Создание, изменение и проверка шаблонов | Да | Да | Да | Нет |
| Изменение тестовых рассылок, сценариев, репетиций и частоты | Да | Да | Нет | Нет |
| Сбор данных, журнал сбора и подключения | Да | Нет | Нет | Нет |
| Пользователи и назначение ролей | Да | Нет | Нет | Нет |
| Реальная отправка | Нет | Нет | Нет | Нет |

Рабочие данные общие: ограничения видимости отдельных клиентов между сотрудниками
не вводились. Каждый пользователь может менять свой пароль. Нельзя менять собственную
роль или роль первоначального суперпользователя. Отключение собственного доступа и
последнего активного администратора запрещено.

Проверки выполняются сервером для каждого запроса; неизвестный API запрещён обычным
ролям по умолчанию. Интерфейс показывает роль и блокирует основные недоступные команды;
серверный запрет действует независимо от интерфейса. После изменения роли новые права
действуют на следующем запросе уже открытой сессии; для обновления интерфейса нужна
перезагрузка страницы. В журнале сохраняются автор и прежняя/новая роль.

Доступ к публичным ссылкам подтверждения подписки, отписки и отслеживания не изменён.
Настройки SMTP не включались. POST тестовой отправки запрещён всем ролям даже при
наличии настроенного транспорта.

Проверка: 418 тестов успешно, включая 8 тестов матрицы прав, прямого API-доступа,
смены роли в открытой сессии, повышения прав только администратором и запрета SMTP.
Проверены Django check, отсутствие новых миграций, синтаксис JavaScript и diff check.
Страница учётных записей проверена в браузере на ширине 320 px; горизонтального
переполнения нет. В рабочую БД добавлена только таблица ролей (миграция 0041),
тестовые пользователи создавались в отдельной тестовой БД. Перед миграцией сохранена
локальная резервная копия SQLite. Клиентская база этим подэтапом не изменяется.

Подэтап завершён для проверки пользователем. Коммит, публикация и следующий этап
не выполнялись.
