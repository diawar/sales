# Servercore и собственный учёт событий — подэтап для проверки

Дата: 12.11.2026. Работа выполнена в локальной копии. Реальная отправка отключена.

## Что реализовано

- Меню **Настройки → Servercore и учёт событий**. Из «Аналитики» есть переход в этот экран.
- Офлайн-проверка наличия SMTP/API-параметров. Интерфейс не показывает пароли, логины и токены.
- Явная кнопка чтения API: ресурс и проверка DNS-статусов домена. Чтение не создаёт ресурсы, не меняет DNS и не отправляет письма. Без реквизитов кнопка недоступна.
- Servercore SMTP-профиль: `smtp.servercore-smtp.com`, 1126 STARTTLS или 1127 TLS. Backend Servercore в этом подэтапе безусловно запрещает отправку. Предыдущая тестовая SMTP-отправка также блокируется при выборе Servercore или его SMTP-хоста, даже если `SALES_SMTP_ENABLED=1`.
- API-адаптер с фиксированными HTTPS-адресами, тайм-аутом 15 секунд, без перенаправлений и вывода исходных ошибок с секретами. Поддержан проектный IAM-токен либо получение и обновление токена сервисного пользователя. Токен кешируется только в памяти процесса до минуты перед истечением срока. По 401/403 интерфейс сообщает о доступе; автоматических повторов нет.
- Подготовка сохранённого шаблона для одного проверочного адреса: персонализация, собственные ссылки переходов, пиксель, ссылка центра подписок, `Message-ID`, `X-Track-ID`, `List-Unsubscribe`. Письмо не передаётся в SMTP и не попадает в очередь отправки.
- Токены случайные (32 байта), в таблицах хранятся SHA-256-хеши. Подготовленный HTML с исходными токенами возвращается только при подготовке и не сохраняется в БД. Срок ссылок — 365 дней.
- Предпросмотр изолирован: нет скриптов, навигации и внешних загрузок. Открытие экрана/iframe не создаёт событие открытия; для проверки есть отдельные кнопки.
- `GET /track/o/<token>.gif`: пиксель, первая загрузка на письмо; `HEAD` не учитывается. Неизвестный/истёкший токен возвращает тот же пиксель без события.
- `GET /track/c/<token>/`: первая загрузка на ссылку и перенаправление на исходный HTTP(S)-адрес шаблона. Направление фиксируется при подготовке и не заменяется параметрами запроса. Повторяющийся URL в одном письме использует одну ссылку. Email/tel-ссылки не переписываются. Неизвестный/истёкший токен — 404.
- Отписка использует существующий `/subscription/<token>/`: GET только показывает страницу; POST с CSRF применяет отписку и записывает событие. Повторная отписка не создаёт дубль. Даже если подписка уже отозвана, нажатие ссылки другого письма фиксируется для этого письма.
- Рабочая отписка использует прежний механизм исключений, но публичный API подготовки на данном этапе создаёт **только тестовые** письма и подписки. Проверочная отписка не меняет рабочие адреса, согласия, запреты или импорт Over-shop.
- Собственный журнал хранится в `TrackedMessage`, `TrackingLink`, `TrackingEvent`, отдельно от `CampaignTestEvent` и тестовых активных/пассивных аудиторий. Есть фильтры режима, письма, email и события, сортировка времени и страницы по 25 записей. Уникальные получатели и число первых событий показаны отдельно. В карточках учитываются выбранные режим/письмо/email; фильтр типа события применяется только к журналу.

## Что проверить

1. Открыть «Настройки». Проверить статусы незаполненных реквизитов и отключённую отправку.
2. Выбрать сохранённый шаблон, оставить `preview@example.invalid`, нажать «Подготовить проверочное письмо».
3. Убедиться, что событий от одного предпросмотра нет. Посмотреть HTML и заголовки.
4. Нажать «Проверить открытие» и «Проверить переход». Повторы не увеличивают счётчики одного письма/ссылки.
5. Открыть проверочную отписку: просмотр не меняет состояние. Нажать кнопку отписки, вернуться и обновить события.
6. Проверить фильтры и режим «Рабочие письма» — тестовые записи туда не попадают.
7. Перезагрузить страницу: раздел и журнал сохраняются. Сам HTML/ссылки предпросмотра намеренно не сохраняются; для нового комплекта нужна новая подготовка.

Проверено в браузере: 1 проверочное письмо, 1 открытие, 1 переход, 1 отписка; события сохранились после перезагрузки. Контакт: зарезервированный `preview@example.invalid`. Письма не отправлялись.

## Настройка на следующем шаге

Пример переменных — `.env.example`. Django не читает этот файл автоматически: параметры нужно передать процессу сервера.

- `SALES_MAIL_PROVIDER=servercore`, SMTP-параметры и `DEFAULT_FROM_EMAIL`.
- `SERVERCORE_RESOURCE_ID`, `SERVERCORE_SENDER_DOMAIN`.
- Либо `SERVERCORE_IAM_TOKEN` (24 часа), либо `SERVERCORE_ACCOUNT_ID`, `SERVERCORE_PROJECT_NAME`, `SERVERCORE_SERVICE_USER`, `SERVERCORE_SERVICE_PASSWORD`. Для автоматического обновления оставить `SERVERCORE_IAM_TOKEN` пустым. Создание сервисного пользователя и назначение прав выполняются владельцем аккаунта отдельно.
- `SALES_PUBLIC_BASE_URL=https://sales.overclockers.kz`. Без него допускается локальная проверка с localhost/127.0.0.1. Вне локального хоста подготовка требует явного публичного HTTPS-origin.
- Миграции `0031` и `0032` создают таблицы и ограничения; существующие клиенты не переносятся и не меняются.
- При развёртывании оставить `/api/*` за авторизацией приложения. Публично без входа должны открываться только `/track/o/*`, `/track/c/*`, `/subscription/*` и нужный публичной странице `subscription-form.js`. Проверить это отдельно на сервере: локальный проект пока полагается на существующую схему защиты при развёртывании.

Реквизиты Servercore не предоставлены. Проверка настоящего аккаунта, SMTP-аутентификации, DNS и публичной доступности не выполнялась. Для API выполнены тесты с подменёнными HTTP-ответами.

## Границы подэтапа

Открытие означает загрузку картинки, переход может быть выполнен защитой почтового сервиса. Это не доказательство прочтения/действия человека. Сейчас сохраняются первые наблюдения, а не все повторные обращения. Уникальность карточек считается по email; журнал содержит события отдельных писем/ссылок. IP и User-Agent не собираются.

Нет реальной отправки, доказательств доставки, автоматического опроса статусов Servercore, включения рабочих аудиторий, счётчиков активности реальных клиентов или повышения квоты. API-метод чтения статуса подготовлен для следующей интеграции. Начальный лимит Servercore — 20 писем за 5 минут; увеличение через тикет. Для рекламы необходимы согласия по условиям провайдера.

Проверки: 123 теста связанных модулей (в том числе 15 новых), `manage.py check`, синтаксис JavaScript и ручной сценарий в браузере. После подэтапа остановиться для проверки заказчиком. Коммит и публикация не выполнялись.
